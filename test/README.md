The project's tests, from unit tests to whole installed servers; most import the built code in `dist/` and the server in `server/`, so build first (`npm run build`). There are a few kinds, told apart by name. `*.test.mjs` files are unit tests for `node:test`, all run by `npm test` (`node --test test/*.test.mjs`, after the build). `*-postgres.mjs` files each run on their own (`node test/<name>.mjs`) against a dedicated PostgreSQL test database with pgmp installed, named by `DATABASE_URL`; they write to it, so never point them at real data (`postgres.mjs`, `versioning-postgres.mjs` and `next-postgres.mjs` also have npm scripts: `test:postgres`, `test:versioning:postgres`, `test:platform:postgres`). `*-live-postgres.mjs` files go further, end to end, mostly with a live browser through Playwright (as does `sharing-postgres.mjs`); `journald-live-postgres.mjs` follows the real system journal and `comparison-live-postgres.mjs` checks live notifications without a browser. `*-browser.mjs` files export checks that `browser.mjs` (`npm run test:browser`) runs in Playwright against the built app, and that `offline-browser.mjs` (`npm run test:offline:browser`) partly reruns on the offline HTML file; `BROWSER` picks chromium, firefox or webkit. The rest run by hand or in their own CI job: `next-platform.mjs` (`npm run test:platform`), `sql-oracle.mjs` and `files.mjs` (which needs the `och-convert` converter built), `docker-smoke.mjs` against the Docker Compose suite, `desktop-bulk.mjs` in the desktop app through tauri-driver, and `server-*.mjs`, which install the server packages; `random-edits.mjs` and `hostile-compiler.mjs` are helpers. [CI](../.github/workflows/ci.yml) runs them all (the server packages in [server-packages.yml](../.github/workflows/server-packages.yml)); see also [Tests and GitHub CI](../README.md#tests-and-github-ci).
