# OpenChronology — Website, Desktop or Offline? Script and Storyboard

**Runtime:** ~2:17 (the scratch narration's cut) · **Format:** animated infographic, **Paper** look · **Aspect:** 16:9
**Audience:** anyone choosing how to use OpenChronology, and especially privacy-minded and offline users who want to know where their data goes before they type anything.
**Purpose:** lay the editions side by side (the website, the browser without an account, the desktop app, the offline file, and a server of your own), say where each keeps a timeline, and show that one file format moves between them.

**How it differs:** it's a comparison, built as one table that fills in column by column. It doesn't teach the editor; it answers "which one, and where's my data?".

**Production notes:**

- Narration is 312 words, about 140 wpm when read.
- **The motif:** a four-column table (Website · Browser, no account · Desktop app · Offline file), with rows "Where it's kept", "Needs a network", "Share and collaborate". Each scene fills one column; the last scene draws the `.ochx` file moving between all of them.
- **timescale.info:** the official public server. **[CONFIRM]** it is live and taking sign-ups before release; if not, say "the website" and drop the address.
- **Accuracy guardrails:**
  - Server timelines start private; administrators of that server can still see them (not encrypted from operators).
  - The desktop app keeps sign-ins only while it runs; connects to up to eight servers; default `https://timescale.info`.
  - The offline file never uses the network and keeps nothing after it closes; export `.ochx`.
  - Comfortable sizes: about 10,000 moments in a browser tab on a fast computer, 1,000 on a phone; the desktop app and the website read only what's on screen, up to the 200,000-moment limit.

**MOTION:** The central window splits into four copies that slide to their columns; row labels fade in on the left.

**OST:** "One editor. Where do you want it?"

**VO:**
"OpenChronology is one editor that runs in several places: on the website, in your browser without an account, as a desktop app, and as a single offline file. It works the same in each. What changes is where your timeline is kept."

## ACT 2 · THE EDITIONS (0:20 – 1:58)

### Scene 2 · 0:20 – 0:50 · The website

**FRAME:** The Website column fills: "Where it's kept: the server, private until you share it"; "Needs a network: yes"; "Share and collaborate: links, embeds, collaborators, forks, history". Beside it, a small account card "timescale.info" with a padlock, and a history list of three saves.

**MOTION:** Cells type in; the padlock closes on "private"; the history list stacks up.

**OST:** "Saved on the server. Private by default."

**VO:**
"On the website, at timescale.info or any OpenChronology server, you sign in and save timelines to your account. Each one starts private. From there you can share a link, embed it on a page, add collaborators, and every save is kept in its history. One honest note: private means hidden from other users, not hidden from the people who run that server."

### Scene 3 · 0:50 – 1:10 · In the browser, no account

**FRAME:** The second column fills: "Where it's kept: only in the open tab"; "Needs a network: to open the page"; "Share and collaborate: export a file". A banner across a small tab icon: "In-memory timeline."; an arrow from it to an `.ochx` file.

**MOTION:** The tab icon flickers as if closing, and the timeline inside it fades: the banner pulses; the arrow to the file draws.

**OST:** "No account? Export to keep it."

**VO:**
"Without an account, you can still start a timeline in the browser. It lives only in that tab, so export it as a file before you close it. Signed in, your browser keeps drafts for you until you save them to the server."

### Scene 4 · 1:10 – 1:36 · The desktop app

**FRAME:** The Desktop column fills: "Where it's kept: `.och` files on your computer"; "Needs a network: no, only to reach a server"; "Share and collaborate: connect to up to eight servers". Badges "Windows", "macOS", "Linux". A folder icon with three `.och` files.

**MOTION:** The files drop into the folder; a network cable icon unplugs and the app keeps working (a moment is added); then a line draws from the app to two server icons.

**OST:** "Your files, on your computer."

**VO:**
"The desktop app, for Windows, macOS and Linux, keeps timelines as files on your own computer, and works with no network at all. Large timelines stay quick, because it reads only what's on screen. When you want to share, connect it to timescale.info, or to your own server, or to several at once."

### Scene 5 · 1:36 – 1:58 · The offline file

**FRAME:** The Offline column fills: "Where it's kept: only while it's open"; "Needs a network: never"; "Share and collaborate: export a file". A single HTML file icon with a crossed-out network symbol, being copied onto a USB stick.

**MOTION:** The file duplicates onto the stick; the network symbol is struck through.

**OST:** "One file. Never online."

**VO:**
"And the offline file is the whole editor in one HTML file. It never uses the network, so you can carry it on a stick or open it on a machine that's never online. Nothing is kept when you close it, so export your work."

## Appendix C · Questions this audience is likely to ask

1. **Which is most private?** The desktop app and the offline file: nothing leaves your computer unless you connect or export.
2. **Can I move a desktop file to the website?** Yes: **Import .och** on the website, or export `.ochx` from the desktop app.
3. **Is there a mobile app?** The website works on phones; there's no separate mobile app.
4. **What about very large timelines?** Use the desktop app or the website; a browser tab without a server is comfortable up to about 10,000 moments.
